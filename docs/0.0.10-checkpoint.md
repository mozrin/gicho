# Gicho 0.0.10 checkpoint

This checkpoint extends the immutable [0.0.9 foundation](0.0.9-checkpoint.md)
with a compact app-bar mark fix and a configurable QR scanner. The tag points
to source verified on the host; it does not claim an installed camera test or
that Harmony CMS integration has been accepted.

## Added API

- `GichoQrScanner<T>` owns QR-only camera capture, permission/error display,
  torch, Back and one accepted route result.
- `QrScannerConfiguration<T>` supplies consumer copy, optional brand and an
  application validator. `QrScanDecision.accept` returns a consumer value;
  `QrScanDecision.reject` keeps scanning with a consumer message.
- The [feature guide](../lib/src/features/scanner/README.md) documents the
  API and camera setup. The [independent Android example](../examples/flutter-scanner/README.md)
  demonstrates employee and menu meanings without importing Harmony.

Gicho does not decide what a QR means or authorize a product action. CMS,
POS or another app supplies its own parser, backend operation and navigation.

## Verification boundary

Gicho analysis, root and focused scanner tests, independent example
analysis/widget tests and an Android debug APK compile are the host checks for
this checkpoint. Real permission, focus, flashlight and QR capture on an
installed device remain owner-run acceptance. Existing consumers must align
their Gicho Git refs to this tag; mixing a tag and another commit for the
same Git package does not resolve through Flutter pub.
