# State

Gicho exposes Flutter Riverpod through its public Flutter entry point:

```dart
import 'package:moztopia/gicho.dart';
```

Wrap the application in `ProviderScope` and use Riverpod directly:

```dart
void main() {
  runApp(const ProviderScope(child: App()));
}

final greetingProvider = Provider((ref) => 'Hello');

class Greeting extends ConsumerWidget {
  const Greeting({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    return Text(ref.watch(greetingProvider));
  }
}
```

Riverpod provides dependency injection, reactive state, asynchronous caching,
provider overrides, lifecycle management, and testable state containers. Keep
application providers in the application; place organization-wide state policy
in this folder only when a shared convention exists.

Barrel files are generated by the barrel workflow utility and must not be
edited manually.

## Configuration reference

State currently has no Gicho YAML parameters and no `state.config.yaml`.
Providers, overrides, persistence, caching, and lifecycle behavior remain
application-owned. Adding `assets/gicho/state.config.yaml` has no effect.
