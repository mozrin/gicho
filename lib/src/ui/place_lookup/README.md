# PlaceLookup

`PlaceLookup` combines a Google map, typed place predictions, and a selected area. `onSelected` gives the consuming app a `PlaceLookupSelection`. The default `coordinatePrecisionKm: 3` places the returned coordinate at the center of an approximate grid cell, reports a 3 km accuracy radius, and omits the exact place ID and label. Set `coordinatePrecisionKm: 0` only when exact coordinates are deliberately required. The map marker and circle use the same returned area center; the callback never receives the exact place in approximate mode. The widget accepts a `PlaceLookupProvider`, so applications can substitute another search provider. `PlaceLookup.fromConfiguration` reads `placeLookup.googleApiKey` from Gicho's resolved consumer YAML and creates the development Google provider.

Set `showMap: false` for search-only use. `mapGesturesEnabled`, `showZoomControls`, `showSelectedCoordinates`, `searchLabel`, `initialLatitude`, `initialLongitude`, `initialZoom`, and `mapHeight` control the presentation. The map and selected-coordinate text are optional; typed suggestions and the selection callback still work without a map.

Google's Flutter map plugin supports Android, iOS, and web. Consumers must enable Maps SDK for Android, Maps SDK for iOS, or Maps JavaScript API and configure the native/web map loader. The focused examples show how to use the same YAML key in each platform loader. The supplied demo key currently supports Places API (New) but the Google map APIs were not activated when this control was built. The Places key in YAML is bundled and readable by users; `GooglePlaceLookupProvider` rejects release mode until a secure credential design replaces this development path. The widget cannot block a deployment pipeline on its own.

Google Places predictions are shown with Google Maps attribution. The package-owned control renders provider errors and clears old suggestions when the query changes. Applications decide what to do with selected coordinates and how to persist them.
